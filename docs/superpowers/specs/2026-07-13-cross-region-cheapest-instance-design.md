# 按地域最低价实例推荐设计

## 背景

云资源自动探测需要在用户选定的地域内发现有库存且价格有效的实例规格。一度尝试在一次请求中遍历所有地域并返回全局最低价，但云厂商库存与价格接口调用量过大，容易造成请求超时，也会让镜像、网络资源与价格结果落在不同地域。当前设计收敛为“按地域查询、按地域推荐”，用户切换地域时重新发起该地域查询。

## 目标

- 读取阿里云账号可访问的地域供前端选择，并只查询当前选定地域的实例规格。
- 比较按量价格和竞价价格，支持 1C1G 等低规格。
- 返回当前地域内可解释的最低价推荐，并保留该地域其他候选用于前端选择。
- 复用现有账号、租户、权限和审计链路，不在仓库或日志中写入 AK/SK。

## 非目标

- 不修改云账号权限模型。
- 不改变实例创建的确认流程、租户校验或危险操作确认。
- 不引入后台定时缓存或跨账号批量比价任务。

## 方案

新增后端聚合接口，由服务端完成单个地域的库存和价格查询，前端按当前地域请求候选结果。地域列表由独立的地域发现接口提供；价格接口不在一次请求中遍历其他地域。接口返回候选的地域、实例规格、CPU、内存、库存、按量价、竞价价和币种，并单独返回当前地域最低价推荐。

推荐规则：

1. 仅将云 API 返回有库存且价格有效的候选纳入可推荐集合。
2. 竞价价和按量价分别比较，默认推荐当前弹性策略对应的最低竞价总价；若竞价价不可用，则回退到最低按量价。
3. 价格相同时优先选择 CPU、内存更高的规格，随后按地域和规格 ID 稳定排序。
4. 前端明确区分推荐候选、普通候选和无价格/无库存候选，展示价格单位；切换地域时清空旧地域资源并重新查询。

## 接口边界

- 聚合接口沿用现有 `/cloud/accounts/:id/*` 路由和账号授权校验。
- 聚合查询失败只影响当前请求地域，并返回可展示的地域级警告。
- 单次价格请求只允许一个地域，避免跨地域并发请求触发云 API 限流和前端超时。
- 不返回任何凭据、签名参数或原始敏感响应。

## 前端交互

自动探测弹窗展示“当前地域最低价推荐”卡片，包含地域、规格、CPU、内存和价格；地域下拉列表来自地域发现接口，切换地域后刷新该地域资源和价格，并在最低价项上增加推荐标记。

## 验证

- 后端单元测试覆盖单地域查询、竞价价优先和按量价回退。
- API/服务测试确认账号授权、默认地域回退、显式地域覆盖、策略覆盖和无候选场景。
- 前端测试确认当前地域最低价卡片、地域切换和候选选择联动。
- 执行 `git diff --check` 及相关 Go/前端测试。
