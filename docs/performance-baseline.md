# Performance baseline

`go run ./scanner/cmd/perf-baseline -case dddd-help -binary ./dddd -arg=-h` writes one `argus.performance-baseline/v1` JSON record. Repeated `-arg` is the shell-friendly form; `-args-json '["-h"]'` is also supported where the shell preserves JSON quoting. The tool measures only external `process_wall`, never emits command arguments or targets, and is not interchangeable with `argus.timing/v1` in-process intervals. The report records the case name, capture time, warmups, samples, min/P50/P95/max, binary SHA-256, optional Arsenal/config SHA-256, Go version, OS and architecture. `-arsenal-file` and `-config-file` add identities without copying their contents. Arguments are bounded but remain visible to normal operating-system process inspection; pass only non-secret, authorized arguments.

Use fixed localhost and POC-off cases for `dddd -h`, an explicit URL warm scan, and an Agent-context case with the same Arsenal identity. For Agent context, aggregate the bounded, target-free `argus.timing/v1` Server events by rule preparation, context initialization and Stage outcome separately; never sum them or label their total as wall time. Capture a G31 before baseline first. Any after capture is only an instrumentation-overhead recheck, not evidence that G31 optimized performance; G32–G36 remain separate optimization goals.

For a repeatable same-process Agent context baseline without dispatching a scan, use `-mode agent-context -agent-config-dir <materialized-config> -arsenal-file <arsenal.db> -config-file <.argus-arsenal.json>`. This mode constructs and closes a fresh `ScanContext` per sample with POC disabled and no target or network activity. It measures context preparation only; it does not replace the separate rule-materialization or end-to-end Agent timing evidence.

The first checked-in baseline set is [`performance-baselines/g31-2026-08-10.json`](performance-baselines/g31-2026-08-10.json). It records that G31 instrumentation did not materially regress the fixed URL case, while the help P95 still exceeds 300 ms and therefore remains work for G32 rather than being marked fixed here.

The G32 comparison is [`performance-baselines/g32-2026-08-10.json`](performance-baselines/g32-2026-08-10.json). It reuses the checked G31 after binary as the before case, then measures the lazy gonmap build with the same identities and warm-up policy. Package inittrace is supporting evidence only: an independent-process gonmap test proves the probe snapshot is absent before `New` or `SetFilter`, while a localhost POC-off scan proves the first protocol stage still recognizes the service.

The G33 comparison is [`performance-baselines/g33-2026-08-10.json`](performance-baselines/g33-2026-08-10.json). It uses a loopback silent TCP fixture to verify that retry, protocol fallback, script/meta follow-up URLs and same-origin redirects consume one target deadline. The report also verifies that a timed-out HTTP target and its dependent stages do not produce reusable negative coverage.

The G35 comparison is [`performance-baselines/g35-2026-08-10.json`](performance-baselines/g35-2026-08-10.json). It measures repeated Agent `ScanContext` creation with an identical, materialized Arsenal and no targets, network calls or POC execution. The materialized manifest must bind both the Server catalog identity and the actual SQLite `package_sha256`; agent-context mode requires `-arsenal-file` and rejects a file whose SHA-256 differs from that manifest before sampling. The benchmark uses that package SHA-256 plus the rule version as the cache identity. G35 shares only immutable parsed Fingerprint, Workflow and Dir knowledge. Task configuration, result maps, URL visits, hooks, cancellation, resume plans, credentials, POC runners and HybridMaps remain per-context.

The G36 comparison is [`performance-baselines/g36-2026-08-10.json`](performance-baselines/g36-2026-08-10.json). It keeps the three response maps task-private but chooses their backend conservatively at Context creation. No-target preparation, confirmed risk validation, and at most eight explicit URL/IP:Port/Domain:Port inputs use memory only when Provider, low-perception, subdomain, directory-probe and HostBind expansion are disabled. Bare hosts, CIDR/ranges, unknown inputs, larger sets and any expanding discovery continue to use cleanup-enabled disk storage. The report retains the same-Arsenal 3/30 Agent-context wall evidence and a repeated factory microbenchmark because the optimized operation falls below the effective Windows wall-clock sample resolution. A zero wall sample is therefore an upper bound, not a claim of zero work.

G36 does not cache Nuclei Runner, compiled templates or execution options. Those objects own targets, callbacks, output, proxy/header variables, Interactsh state, resume data and input stores, while risk validation must re-read and hash the exact approved POC files for each execution. The only Nuclei change closes the temporary non-HTTP input HybridMap when later HTTP client construction fails.

To reproduce G35, run `go run ./scanner/cmd/perf-baseline -mode agent-context -case g35-agent-context-after -agent-config-dir ./config -arsenal-file ./data/arsenal.db -config-file ./config/.argus-arsenal.json -warmups 3 -samples 30`. A legacy manifest without `package_sha256` is deliberately rejected by the benchmark and rematerialized once by the Agent/CLI activation path; do not hand-edit an identity to bypass package verification.

To reproduce the G33 process case, run a local TCP listener that accepts connections without sending bytes, then invoke `perf-baseline` with 3 warmups, 30 samples and the CLI arguments `-t http://127.0.0.1:<port> -Pn -nd -npoc -force -wto 1 -wt 1 -ot text`. Keep the fixture, Arsenal, materialized config, binary and machine fixed between before and after captures; the report intentionally stores hashes rather than command output or target data.
