# 分布式资产探测与漏洞识别平台 XMind 脑图提纲

## 1. 汇报版主结构

- 分布式资产探测与漏洞识别平台
  - 平台目标
    - 统一资产探测、指纹识别、漏洞识别能力
    - 支持多节点横向扩展，提升扫描吞吐
    - 支持规则中心化管理与热更新
    - 支持任务调度、失败恢复、结果聚合
    - 支持后续多租户、容器化、审批流扩展
  - 整体架构
    - 服务端控制面
      - 任务编排中心
      - 调度中心
      - 规则中心
      - 节点管理中心
      - 结果聚合中心
    - 扫描 Agent 数据面
      - Agent 管理器
      - 任务执行器
      - 扫描引擎
      - 本地规则缓存
      - 容器化隔离执行
    - 存储与基础设施
      - PostgreSQL
      - Redis
      - 对象存储/文件存储
  - 服务端
    - 任务管理
      - 任务创建
      - 目标标准化
      - 任务拆分
      - 状态流转
      - 超时控制
      - 重试恢复
    - 调度管理
      - 待执行队列
      - 运行中任务管理
      - 节点标签匹配
      - 节点容量控制
      - 优先级调度
      - 异常任务回收
    - 规则中心
      - 指纹库管理
        - 被动 Web 指纹
        - 主动目录指纹
        - 服务 Banner 指纹
      - Workflow 管理
        - 指纹到 POC 的映射关系
        - root/base/dir/dir-fallback 规则
      - POC 管理
        - nuclei POC
        - GoPoc
        - EXP 元数据
      - 规则治理
        - 版本控制
        - 审批发布
        - 哈希校验
        - 回滚机制
    - 节点管理
      - 节点注册
      - 心跳保活
      - 在线状态监控
      - 节点标签与能力
      - 节点容量统计
      - 掉线节点任务接管
    - 结果中心
      - 资产结果
        - IP
        - Port
        - Protocol
        - URL
        - 标题
        - 证书信息
      - 指纹结果
        - 产品名称
        - 命中规则
        - 命中路径
      - 漏洞结果
        - 漏洞名称
        - 严重度
        - POC 类型
        - 漏洞证据
      - 展示输出
        - 实时大屏
        - 任务详情
        - 漏洞报告
        - 资产报告
  - 扫描 Agent
    - Agent 管理器
      - 节点注册
      - 心跳上报
      - 拉取任务
      - 拉取规则版本
      - 本地运行状态维护
    - 任务执行器
      - 单任务上下文
      - 并发控制
      - 超时终止
      - 取消中断
      - 结果流式回传
    - 扫描执行链
      - 空间引擎资产获取
        - Fofa
        - Hunter
        - Quake
      - 子域名枚举
      - 存活探测
      - 端口扫描
      - 协议识别
      - Web 探针
      - 主动目录探测
      - 被动/主动指纹识别
      - Workflow 映射
      - nuclei 漏洞检测
      - GoPoc 漏洞检测
    - 本地规则缓存
      - 规则版本缓存
      - 哈希校验
      - 增量更新
      - 失败回滚
    - 隔离执行
      - 当前阶段
        - Agent 进程内直接执行
      - 演进阶段
        - Docker Runner
        - 每任务独立容器
        - 代理独立配置
        - CPU/内存限制
  - 关键业务闭环
    - 任务闭环
      - 用户创建任务
      - 服务端拆分任务
      - 调度器分发任务
      - Agent 执行扫描
      - 结果实时回传
      - 服务端聚合展示
    - 规则闭环
      - 规则提交
      - 规则审核
      - 版本发布
      - Agent 同步
      - 扫描命中验证
      - 规则优化回滚
    - 故障闭环
      - 节点掉线识别
      - 运行中任务标记
      - 任务重新入队
      - 新节点接管执行
  - 当前实现基础
    - 已有控制面
      - server/api
      - server/grpc
      - scheduler/queue
      - db
    - 已有数据面
      - agent/worker
      - engine/pipeline
    - 已有扫描能力
      - 指纹识别
      - Workflow 映射
      - nuclei
      - GoPoc
    - 当前缺口
      - 规则同步不完整
      - 调度能力偏简单
      - 结果结构化不足
      - 容器隔离尚未落地
  - 分阶段建设
    - 第一阶段
      - 完整规则同步
      - 任务状态机增强
      - 队列超时回收
      - 结果分层落库
    - 第二阶段
      - 标签调度
      - 优先级调度
      - 容器化执行
      - 任务取消与中断
    - 第三阶段
      - 多租户
      - 审批流
      - AI 辅助规则审核
      - 平台化运营能力

## 3. 汇报时建议只保留的一级分支

- 平台目标
- 服务端
- 扫描 Agent
- 关键业务闭环
- 当前实现基础
- 分阶段建设

如果现场汇报时间比较短，建议把“结果中心”和“规则中心”放在服务端下面重点展开，把“扫描执行链”放在 Agent 下面单独展开，这样结构最稳定，也最接近你参考图的表达方式。
